# v41 Iris Implementation Plan

Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v41 "Iris": shareable links. One click turns the current design, an Interactive Tour, or a Before / After compare into a public URL (`/s/<id>`) that opens in any browser, unfurls with a preview card in chats, can be embedded with an iframe, and can be deleted by the person who made it. No account and no Supabase.

**Architecture:** Shares live in Vercel Blob under `shares/<id>/`: the rendered images (`0.webp`, `1.webp`, ...), a `poster.webp` for link previews, and a `manifest.json` that describes the share. The browser uploads images straight to Blob with short-lived per-file tokens minted by a serverless function, so the 4.5 MB function body limit never applies. A second function validates and writes the manifest. The manifest holds only file *names*, never URLs, so a share can only point at its own files. `/s/<id>` is rewritten to a function that injects Open Graph tags and the manifest into the static viewer page (a new Vite input at `s/index.html`). The viewer mounts the same Tour and Compare players that the HTML exports use, after those players are pulled out of their template strings into shared modules. Ownership is a stateless HMAC key: no database.

**Tech Stack:** Vanilla JS + Vite, Vercel serverless functions + Vercel Blob (`@vercel/blob`), Node `assert` tests in `scripts/regression-tests.mjs`, ESLint + knip via `npm run check`, Playwright for browser checks and the site shot.

## Global Constraints

- Codename **Iris** (the part of the eye that lets the light in, and a link is how other people get to see your work). Header and What's new heading `v41 · Iris`; `whats-new.js` `CURRENT_VERSION = '41.0'`. `package.json` stays at 40.0.0; the `ship` skill bumps it.
- New feature modules start with a `// v41` tag comment.
- New localStorage keys use the `glint_` prefix (this plan adds `glint_shares`).
- `src/share/share-core.js` is imported by the tests and by `api/*`, so it must not touch `window` / `document` and must not import anything browser-only.
- No design state changes, so no `SCHEMA_VERSION` or `DOC_VERSION` bump and no `snapshot()` change.
- The viewer never renders HTML from a manifest. Every string goes through `textContent`; every image path is a validated file name resolved under the share's own prefix.
- Marketing pages, the viewer page chrome, and changelog copy are built under `.claude/skills/taste-skill` (read it before Tasks 7 and 10). Zero em or en dashes, no emoji, at most one middle dot per line, real images only.
- Do not use the superpowers skills to run this plan.
- Commit messages: one `-m` flag per paragraph, no heredoc (CLAUDE.md, Windows host).
- `npm run check` (lint, knip, tests, build) must pass at the end of every task.

## Decisions made in this plan

1. **Vercel Blob, not Supabase.** The current Share button needs the visitor to connect their own Supabase project and sign in, so in practice almost nobody can use it. Blob runs on the deployment's own token (like `OPENAI_API_KEY` for hosted AI), so links work for every visitor with no account. The old Supabase share path is removed in Task 6. Retiring Supabase everywhere else is Task 11 and needs a go-ahead (see "Dropping Supabase" below).
2. **Three kinds in v41: Image, Tour, Compare.** Image covers single designs and board exports. Roll contact sheets and Pins are out of scope.
3. **Data, not HTML, is uploaded.** Serving a user-uploaded HTML file from the Glint origin would let anyone host script on our domain. The viewer is our own code; the manifest is data checked by `normalizeManifest()` on the server and again in the viewer.
4. **File names, not URLs, in the manifest.** `"src": "3.webp"` resolves to `<blob base>/shares/<id>/3.webp`. A name must match `^(\d{1,2}|poster)\.(webp|jpg|png)$`. There is no URL to validate and no way to point a share at someone else's files.
5. **Stateless ownership.** `key = base64url(HMAC-SHA256(SHARE_SIGNING_SECRET, 'own:' + id))`. The same key commits the manifest and later deletes the share. The editor keeps it in `glint_shares`, and a "manage link" (`/s/<id>#key=...`) lets someone delete from another browser. The hash never reaches the server unless they press Delete.
6. **Links do not expire.** People paste these into docs and changelogs. A daily sweep removes only uploads that were never committed (older than 24 hours).
7. **Not configured means downloads only.** `GET /api/share-status` returns `{ enabled }`. Without `BLOB_READ_WRITE_TOKEN` and `SHARE_SIGNING_SECRET`, or under plain `npm run dev` where `/api` does not run, the Share panel says links are not set up here and the HTML exports keep working.
8. **Report link only when there is somewhere to report to.** The site has no contact address today. The viewer shows "Report this link" only when `SHARE_REPORT_EMAIL` is set.

```js
// v41 — Share links: DOM-free core shared by the editor, the viewer and api/*.
export const LIMITS = {
  fileBytes: 8 * 1024 * 1024, shareBytes: 40 * 1024 * 1024,
  steps: 30, hotspots: 12, title: 120, label: 80, body: 400,
  types: ['image/webp', 'image/jpeg', 'image/png'],
};
const ID_RE = /^[A-Za-z0-9]{12}$/;
const ASSET_RE = /^(\d{1,2}|poster)\.(webp|jpg|png)$/;
const HEX_RE = /^#[0-9a-f]{6}$/i;

export const isShareId = (id) => typeof id === 'string' && ID_RE.test(id);
export const isAssetName = (n) => typeof n === 'string' && ASSET_RE.test(n);
export const assetPath = (id, name) => `shares/${id}/${name}`;
export function extFor(type) { return { 'image/webp': 'webp', 'image/jpeg': 'jpg', 'image/png': 'png' }[type] || null; }

// randomBytes(n) -> Uint8Array, injected (crypto.getRandomValues in the
// browser, crypto.randomBytes in Node) so the module stays environment-free.
export function newShareId(randomBytes) { /* 12 base62 chars, rejection-sampled */ }

// hmac(secret, message) -> Promise<Uint8Array>, injected the same way.
export async function shareKey(hmac, secret, id) { /* base64url(hmac(secret, 'own:' + id)) */ }
export async function verifyKey(hmac, secret, id, key) { /* constant-time compare */ }

// Returns a clean manifest or throws Error('bad manifest: <field>').
// Unknown keys are dropped, numbers clamped, strings trimmed and cut to LIMITS,
// colors checked against HEX_RE, every image field checked with isAssetName.
export function normalizeManifest(raw, { id, now }) { /* ... */ }
```

Manifest shape (`v: 1`):

```js
{ v: 1, id, kind: 'image' | 'tour' | 'compare', title, createdAt, poster: 'poster.webp' | null,
  image:   { src, w, h, alt },
  tour:    { steps: [{ src, w, h, autoAdvanceMs, hotspots: [{ x, y, w, h, label, callout: { title, body, side } }] }] },
  compare: { before, after, w, h, rect: { x, y, w, h }, orientation: 'vertical' | 'horizontal', split,
             labels: { enabled, before, after, position: 'top' | 'bottom' },
             divider: { color, width, handle } } }
```

Only the block matching `kind` is kept. `w`/`h` are integers 1..8192, fractions 0..1, `autoAdvanceMs` 0..60000, `side` one of `top|bottom|left|right` (default `bottom`), divider `width` 0..12.

Tests to add:

- [ ] `newShareId` gives 12 base62 characters and `isShareId` accepts it.
- [ ] `isAssetName` accepts `0.webp`, `29.jpg`, `poster.webp`; rejects `../x.webp`, `a.webp`, `0.svg`, `0.webp?x`, `https://...`.
- [ ] `normalizeManifest` drops unknown keys and the blocks for other kinds, clamps a hotspot at `x: 4` to 1, cuts a 500-character title to 120, rejects a tour with 31 steps, rejects a compare whose `before` is a URL, replaces a bad divider color with `#ffffff`.
- [ ] `shareKey` is stable for one id and secret, differs across ids, and `verifyKey` rejects a key with one character changed (tests use Node `crypto.createHmac`).

### Task 3: Share API and the store adapter

**Files:** create `api/_share.js`, `api/share-status.js`, `api/share-create.js`, `api/share-commit.js`, `api/share-manifest.js`, `api/share-delete.js`, `api/share-sweep.js`; modify `package.json` (`npm install @vercel/blob`), `scripts/regression-tests.mjs`, `docs/BACKEND.md`.

`api/_share.js`:

```js
export const hmacNode = (secret, msg) => createHmac('sha256', secret).update(msg).digest();
export function json(res, status, body, headers) { /* ... */ }
```

Routes:

- [ ] `GET /api/share-status` returns `{ enabled }`. Cache `no-store`.
- [ ] `POST /api/share-create` with `{ kind, files: [{ type, size }], poster: { type, size } }`. Checks kind, counts, types, sizes against `LIMITS`. Makes an id and its key. Names files itself (`0.webp`, `1.webp`, ..., `poster.webp`) and mints one client token per file with that exact pathname, its content type, its size cap and a 15 minute `validUntil`. Returns `{ id, key, uploads: [{ name, pathname, token }] }`. In memory mode the token is a fake and the client upload is replaced in tests by a direct `store().put`.
- [ ] `POST /api/share-commit` with `{ id, key, manifest }`. Verifies the key, runs `normalizeManifest`, lists `shares/<id>/` and checks every file the manifest names was uploaded and the total is under 40 MB, then writes `manifest.json` with `allowOverwrite: false` (a second commit returns 409). Returns `{ url: SITE + '/s/' + id }`, where `SITE` is the request's host so previews link to themselves.
- [ ] `GET /api/share-manifest?id=` returns the manifest plus `base` (the public folder URL) or 404. `Cache-Control: public, max-age=60, s-maxage=86400`.
- [ ] `POST /api/share-delete` with `{ id, key }`. Verifies the key and deletes every file under the prefix. Returns 204, or 404 when already gone.
- [ ] `GET /api/share-sweep` (cron). Requires `Authorization: Bearer ${CRON_SECRET}`. Lists `shares/` folded by folder, deletes folders with no `manifest.json` whose newest file is older than 24 hours. Logs a count.
- [ ] Every route uses `requirePost` / `parseBody` / `ApiError` from `api/_shared.js` where they fit, and returns 501 `{ error: 'Sharing is not set up' }` when `shareConfig().enabled` is false.

Tests (memory store, mock `req`/`res`):

- [ ] create then upload then commit then manifest round-trips, and the manifest `base` ends with `shares/<id>/`.
- [ ] commit with a wrong key is 403; a second commit is 409; a manifest naming a file that was not uploaded is 400; an SVG type at create is 400; 31 tour files at create is 400.
- [ ] delete with the right key removes every file and the manifest route then returns 404.
- [ ] sweep without the cron header is 401; with it, it removes an uncommitted folder older than 24 hours and keeps a committed one.

`docs/BACKEND.md`: add the routes and the three env vars, and replace "Supabase is still used separately for ... share links" with the Blob note.
