# Plan: v37 Exposure (Roll: batch develop)

## Context
v37 Exposure turns Glint's small batch export into a full workflow. You load a "roll" of screenshots, style them all with one design, change single shots where needed, and export ("develop") the whole roll in several sizes. Today's batch path (`src/features/batch-export.js` `exportBatch()`, lines 122-154) has these limits:
- PNG only, at the canvas size only.
- No per-shot changes, no cancel.
- Not saved: `state.batch.images` holds only `{id, name}`, the image data is thrown away (`set-ui.js:208`), and it isn't in undo or project saves.

v37 replaces that path. It does not run next to it as a second batch system.

The working name for the feature in code and UI is **Roll** (state key `roll`), because the codename moved from Darkroom to Exposure.

## Design

### State: `state.roll` (new, in `src/state/state.js`)
```js
roll: {
  shots: [ { id, name, src /* capped dataURL */, w, h, overrides: {} } ],  // array order = roll order
  sizes: [ { label: 'canvas' } ],          // or { label, width, height }
  presetId: 'png-1x',                      // export-presets.js id (format/quality/scale)
  naming: '{n}-{name}-{size}',
  smartFit: { enabled: true, phone: 'iphone16pro', tablet: 'ipadpro', wide: 'chrome' },
  activeShot: null,                        // runtime-only, stripped from snapshot + save
}
```
- Decoded images go in the existing `imageRegistry` (`state.js:298`), keyed by shot id, the same way batch does today.
- `src` is made with `imageToDataUrl(img, 2000, 'image/jpeg', 0.9)` (`serialize.js:121`), the same cap as `getImageDataURL()`.
- Show a size warning above 30 shots.

### Pure logic: `src/render/roll-core.js` (new, DOM-free, so the Node tests can import it)
- **`ROLL_OVERRIDE_FIELDS`**: the fields a single shot can change. Each is a dot-path:
  - `imageTransform` (crop and focal point)
  - `textOverlay.content`
  - `compare.beforeSrc`
  - `annotations`
  - `deviceFrame.type` (a manual frame for one shot beats smart fit)
- **`getByPath` / `setByPath`**: move these private helpers out of `merge-studio.js` (lines 45-52) into a shared `src/state/paths.js`, and point merge-studio at the shared copy.
- **`diffOverrides(base, current)`** returns `{path: value}` for the fields that differ from the roll's design.
- **`applyOverrides(target, overrides)`** writes those values in.
- **`classifyAspect(w, h)`** sorts a shot by its height-to-width ratio:
  - h/w ≥ 1.4 is `phone`
  - h/w ≥ 1.05 is `tablet`
  - anything flatter is `wide`
- **`smartFrameFor(shot, smartFit, state)`** returns a `deviceFrame.type`. It returns nothing when:
  - 3D mockup or Surface is turned on, or
  - the shot sets its own frame override.
- **`fileName(pattern, { n, name, size, pad })`**: fills `{n}`, `{name}` and `{size}`, and cleans the result with merge-studio's `sanitize` (moved into `paths.js` as well).

### Feature module: `src/features/roll.js` (`// v37`, `bindRoll()`, called from `main.js`)
- **Add shots:**
  - From files, drag-and-drop, or a folder picker (`<input webkitdirectory>`).
  - Reuse `set-ui.js` `loadImageFile(file)`, but keep the `dataUrl` it returns.
  - Remove a shot, or reorder by dragging (one undo step each).
- **Contact sheet:**
  - A grid of thumbnails. Each one is rendered offscreen with `renderAtSize` (`render.js:264`), using the shot's image plus its overrides plus smart fit, then turned into an image with `campaign-targets.js` `thumbDataUrl` (line 21).
  - The grid refreshes about 300 ms after design changes, through `window.__rollRefresh`, which `render()` calls (preview only). Only visible tiles are redrawn.
- **Editing a single shot (the shot / roll switch):**
  - Clicking a tile makes that shot active and saves the roll's current values of the override fields.
  - It then applies the shot's image, smart frame and overrides to the live state and calls `render()`.
  - In "This shot" mode, any change to an override field is recorded as that shot's change. On leaving the shot, or switching to "Roll", the plan:
    - runs `diffOverrides` against the saved roll values,
    - stores the result in `shot.overrides`,
    - puts back the roll's values for those fields.
  - Changes to other fields always apply to the whole roll. A hint line says so.
  - The flow follows merge-studio's `applyRow` / `stopPreview` pattern (preview without touching undo, then restore).
- **`developRoll({ signal })` (the export):**
  - For each shot × size:
    1. Apply the shot's image, smart frame and overrides.
    2. Render it with `renderAtSize`, or `renderInto` for the canvas size.
    3. Scale it up by the preset's scale.
    4. Encode it with the preset's format and quality.
  - File names come from `fileName(...)`.
  - It yields between shots with `setTimeout 0`, so the page stays responsive.
  - Progress shows in `#roll-progress`. Cancel uses an `AbortController`, triggered by a Cancel button and by the action button on the `showNotification` toast (`{ action }`).
  - A `finally` block restores the roll's design and image.
  - Output is one ZIP via `downloadZip` (`batch-export.js:18`).
  - Optional: a PDF contact sheet with jspdf, following the `pages.js` `exportDeckPDF` pattern.
- **Shared encoder:** move the format → mime/extension mapping and the "PNG gets no quality setting" rule (`export-presets.js:43-59`) into `encodeCanvas(canvas, format, quality)`. Both `exportScaled` and the roll export use it.

### Replacing batch
- Remove the "Batch" tab from the App Store Sets section and delete `#batch-controls` (`editor/index.html:936-976`).
- Remove `exportBatch` and the batch parts of `set-ui.js`. Keep `downloadZip`: either leave `batch-export.js` with only that function or rename the file to `zip.js`.
- `state.mode === 'batch'` goes away. A saved `mode: 'batch'` falls back to `single`.
- The old Cmd-K commands `mode-batch` and `export-batch` (`palette.js:223,225,283`) become Roll commands.
- Knip will catch any leftovers.

### Sidebar and Cmd-K
- A new section `<div class="sidebar-section" data-group="export">` titled "🎞 Roll" (Pro only, so no `data-simple`). Controls are wired through `elements.js`, and `updateUIFromState()` updates the Roll controls.
- Cmd-K commands, with the same `when()` checks as the existing ones: `roll-add`, `roll-develop`, `roll-next-shot`, `roll-prev-shot`, `roll-scope-toggle`.
- No new global shortcuts.

### Undo and persistence
- `history.js` `snapshot()`: add `roll`, without `activeShot`.
- `serialize.js`: add `roll` to `PROJECT_FIELDS` (not the lean fields, because shots carry image data).
- Bump `SCHEMA_VERSION` from 21 to 22. Add `ensureRollDefaults(design)`, which fills defaults and drops broken shots. Wrap it outermost in the `normalizeProject` chain (line 230).
- `document.js` `applyDesignToState`: after loading, `await ensureRollImages(roll)`, which decodes each `src` into `imageRegistry`. This mirrors `ensureCompareImage`.
- Old v36 projects: `normalizeProject` gives them an empty roll.
